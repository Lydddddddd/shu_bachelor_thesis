\chapter{基于全局预测的专家提前调度方法}
\label{chap:global_schedule}

\section{问题描述与设计动机}
在 VL-MoE 推理系统中，MoE 层的专家访问由 Router 动态决定。对于显存受限的部署场景，专家权重往往无法全部常驻 GPU，而需要在 CPU 与 GPU 之间按需搬运。若系统等到真实访问发生时才开始加载专家，就会在专家计算路径上引入明显等待时间，从而放大 TTFT 和解码阶段时延。

围绕这一问题，本文将其定义为面向 offload 场景的\textbf{专家提前调度问题}：利用当前层 Router 已经产生的路由信号，预测未来若干层更可能激活的专家集合，并在真实访问发生前完成预取、驻留和替换决策，从而把一部分等待时间前移到当前层的计算窗口中。现有系统工作已经从 KV cache、prefill/decoding 解耦以及 expert offloading 等角度探索过 serving 优化，代表性方法包括 PagedAttention、DistServe、MoE-Infinity 和 ExpertFlow\cite{kwon2023pagedattention,zhong2024distserve,xue2024moeinfinity,he2024expertflow}。本文进一步利用\textbf{路由可预测性}，把优化对象从“被动处理专家访问”推进到“主动规划专家访问”。

与纯文本 MoE 相比，Qwen3-VL 这类多模态模型还具有额外的条件变量。图像 Token 与文本 Token 的路由密度、位置分布和上下文稳定性并不相同，因此本文在预测器输入和调度器决策中都显式引入模态信息，而不是把它当成后处理噪声。

从形式化角度看，设第 $l$ 层输入的 Token 集合为 $\mathcal{X}^{(l)}=\{x_i^{(l)}\}_{i=1}^{n_l}$，Router 为每个 Token 选择 Top-$k$ 专家集合
\begin{equation}
\mathcal{A}_i^{(l)} = \mathrm{TopK}\big(\mathrm{Router}(x_i^{(l)})\big), \qquad \mathcal{A}_i^{(l)} \subseteq \mathcal{E},
\end{equation}
其中 $\mathcal{E}=\{e_1,e_2,\ldots,e_M\}$ 表示全部专家集合，$M$ 为专家总数。
本章的目标是在保证预测额外开销可控的前提下，利用当前层可观测信号逼近未来层的真实激活集合，从而尽可能减少专家加载时延、数据搬移量和等待开销。

\section{数据采集与样本构建}
为了让预测器直接对真实 VL 路由模式建模，本文没有复用旧的纯文本 MoE 语料，而是重新采集了 Qwen3-VL 的 fresh 路由 trace。采集链路由三步组成：
\begin{enumerate}
    \item 在 Qwen3-VL 推理过程中对 MoE Router 增加 hook，记录每层的 router 概率、Top-$k$ 专家、Token 位置、输入标识和模态标识；
    \item 将单次请求的逐层路由组织为 token 级样本，保留 layer-0 路由信号以及后续层监督标签；
    \item 使用构建脚本将原始 trace 转换为训练所需的 Parquet 数据集，再切分为训练集和验证集。
\end{enumerate}

在当前实验中，fresh 数据集共包含 8347 个 token，其中训练集 7268 个 token，验证集 1079 个 token；按模态统计，图像 token 为 6734，文本 token 为 1613。数据集覆盖了多项选择、描述、推理和图文组合等样本，因此能够提供较丰富的路由模式。

\section{全局路由预测器设计}
\subsection{输入特征}
本文实现的预测器是一个 layer-0 条件化的全局路由预测器。运行时只需要观察第 0 层 Router 输出，就可以一次性预测后续所有 MoE 层的专家使用情况。最终版本采用带附加特征的配置，即在基础路由信号之外，还引入 Token 位置、输入标识、模态信息和路由统计量。

对于单个 Token，输入特征包括：
\begin{enumerate}
    \item layer-0 router 概率向量 $\mathbf{g}_i^{(0)} \in \mathbb{R}^{M}$；
    \item layer-0 Top-$k$ 专家的一热或 multi-hot 表示 $\mathbf{m}_i^{(0)} \in \{0,1\}^{M}$；
    \item token 位置编号及其 bucket 化嵌入；
    \item input id 的哈希嵌入；
    \item 是否为视觉 token 的模态嵌入；
    \item router 统计量，包括 Top-$k$ 概率质量、最大概率和归一化熵。
\end{enumerate}

将这些特征拼接后，得到单个 token 的全局预测输入
\begin{equation}
\mathbf{f}_i = \big[\mathbf{g}_i^{(0)} \,\|\, \mathbf{m}_i^{(0)} \,\|\, \phi(\text{pos}_i) \,\|\, \psi(\text{input\_id}_i) \,\|\, \eta(\text{modality}_i) \,\|\, \rho(\mathbf{g}_i^{(0)}, \mathbf{m}_i^{(0)})\big],
\end{equation}
其中 $\rho(\cdot)$ 表示由 router 概率与 Top-$k$ one-hot 计算得到的统计特征映射。

\subsection{网络结构}
预测器采用“共享骨干 + 多层输出头”的轻量结构。首先将路由信号和 token 信号投影到同一隐空间，再经过多层 MLP backbone 提取稳定特征，最后为每一层设置独立输出头，直接输出该层的专家 logits。对应到实现，核心模块位于 \texttt{expertflow\_offload/expertflow\_offload/qwen3vl\_global.py}。其中 \texttt{route\_proj} 负责处理 router 概率和 Top-$k$ one-hot，\texttt{token\_proj} 负责处理 token 位置，\texttt{use\_extra\_features} 打开后再接入 input id、模态和 route statistics。

\subsection{训练目标}
由于一个 token 在同一层可能激活多个专家，因此本文将该任务建模为多标签学习问题。设真实标签为 $\mathbf{y}\in\{0,1\}^{H\times M}$，预测 logits 为 $\hat{\mathbf{z}}\in\mathbb{R}^{H\times M}$，则训练目标为
\begin{equation}
\mathcal{L}_{\mathrm{pred}} = \sum_{h=1}^{H} \omega_h \cdot \mathrm{BCEWithLogits}\big(\hat{\mathbf{z}}^{(h)}, \mathbf{y}^{(h)}\big),
\end{equation}
其中 $\omega_h$ 为不同预测视野的权重。训练完成后，模型在验证集上的 best mean recall 达到 0.7219，early/mid/late 三个视野的 recall 也都稳定在较高水平，说明 layer-0 条件化预测已经具备进入运行时调度链路的基础。

\section{预测驱动的专家预取与缓存调度}
\subsection{加权预取策略}
系统并不把所有预测结果无差别搬入 GPU，而是根据置信度、层距和预算进行筛选。对于未来第 $h$ 层的候选专家 $e$，调度分数可写成
\begin{equation}
s(e,h) = \alpha_h \cdot p(e,h) \cdot \max(p_1-p_2,0),
\end{equation}
其中 $p(e,h)$ 是预测概率，$p_1$ 与 $p_2$ 分别为 top-1 和 top-2 预测概率，$\alpha_h$ 是层距衰减项。随后系统按分数从高到低保留有限数量的候选专家，并由 \texttt{select\_weighted\_global\_prefetch\_plan()} 将其转换为可执行的预取列表。

这一设计的核心思想是：不是“看见预测就搬运”，而是“只有高置信、近未来、收益大于成本的专家才进入缓存”。因此，预算、置信度阈值、最小 margin 和每层 key 上限共同决定最终的预取行为。

\subsection{ExpertFlow、DALI 与 Hybrid}
本文在同一套预测器上实现了三类调度方式。

\textbf{ExpertFlow 风格}策略强调按预测权重做稀疏预取，即根据全局预测分数直接挑选少量专家进入 GPU cache；它更适合在预测质量较高、预算较紧的情况下使用。

\textbf{DALI 风格}策略强调 working-set 重排，即允许缓存围绕预测工作集重新整理，而不是只做增量式 prefetch；它更适合希望缓存结构与未来工作集更贴近的场景。

\textbf{Hybrid} 则先利用 DALI 风格更新缓存内部的工作集状态，再用 ExpertFlow 风格的加权预取补充候选 key。换句话说，Hybrid 不是把两种方法简单相加，而是同时保留工作集视角和稀疏控制能力。

\subsection{预测错误与回退机制}
预测驱动的调度不可避免会出现误预测，因此系统需要在正确性与收益之间做折中。本文采用两级回退机制：
\begin{enumerate}
    \item 对未命中的真实专家立即同步加载，保证计算可继续；
    \item 将命中情况反馈到缓存分数，降低低价值专家的长期驻留优先级。
\end{enumerate}

因此，本文的目标不是让预测永远正确，而是让正确预测尽量提前生效，同时把错误预测控制在可接受范围内。

\section{系统实现与复杂度分析}
整个原型实现拆分为三个阶段：
\begin{enumerate}
    \item 数据采集与构建：\texttt{collect\_qwen3vl\_global\_scratch\_data.py}、\texttt{build\_qwen3vl\_global\_scratch\_parquet.py}；
    \item 预测器训练：\texttt{train\_qwen3vl\_global\_predictor.py}；
    \item 在线集成：\texttt{qwen3vl\_global.py}、\texttt{global\_scheduling.py}、\texttt{run\_qwen3vl\_real\_offload\_benchmark.py} 与 \texttt{run\_qwen3vl\_end\_to\_end\_offload.py}。
\end{enumerate}

从复杂度上看，预测器的主要代价来自 MLP 前向和多层输出头，但其输入维度和参数规模都远小于 MoE 专家权重搬运成本，因此适合作为调度前置模块。调度器本身的复杂度主要来自候选专家排序和缓存替换，均低于专家前向与权重传输。若将 token 数、预测视野和候选专家数分别记为 $B$、$H$ 与 $K$，则预测与筛选的开销可近似写为
\begin{equation}
\mathcal{O}(B \cdot H \cdot K),
\end{equation}
而缓存更新和排序通常可压缩到候选集合规模上的 $O(K\log K)$。

\section{本章小结}
本章从 fresh 路由数据出发，构建了一个 layer-0 条件化的全局预测器，并在此基础上设计了 ExpertFlow、DALI 和 Hybrid 三类专家调度策略。与纯静态缓存不同，本文方法把预测信号直接引入专家预取、缓存重排和回退机制中，使得专家搬运从“访问后处理”变成“访问前准备”。下一章将围绕真实 CPU-GPU expert offload 微基准对该方法进行实验验证。
